## Executable and compatibility changes

- Both send helpers require jq 1.6+ for descriptor-fed `--rawfile` encoding. This avoids the observed long-line UTF-8 corruption with `jq -Rs` on jq 1.7.1-apple; the internal jq cause is not established here. Encoding failures stop before transport and preserve jq status. All supported argv strings remain data; OS argv cannot contain NUL. Address validity and API content limits remain SendGrid's responsibility.
- Both send helpers split the curl status/body with Bash parameter expansion instead of GNU-only `head -n-1`, which failed on macOS after the request. They stream JSON on curl stdin and validate the key alphabet before passing authentication through a config descriptor. Neither jq nor curl receives message fields as argv. The standalone Bash curl examples use the same transport boundary without depending on sibling scripts. Original helper arguments, environment access, shell history and output logs still need protection; large file content is buffered, not unbounded streaming.
- Sends disable default curl configuration and environment proxies, retain HTTPS/TLS verification, do not follow redirects, and use 10/60-second connect/total timeouts. HTTP errors return nonzero. Transport failures preserve curl status and report unknown delivery; there is no automatic retry or dry-run.
- The plain-text part remains unchanged. Its HTML alternative escapes markup first, then turns CRLF, LF and CR into `<br>` through jq.
- `verify-inbound-setup.sh <hostname>` retains dig/nslookup MX checks, requires an exact case-normalized exchange field (one optional terminal dot), and reports resolver failures separately. The former `<hostname> <webhook-url>` invocation intentionally fails, with a migration message. MX results do not establish global DNS propagation, webhook reachability, authentication or delivery.
- The manual webhook example uses `--form-string` for literal fields, because curl `-F` treats leading `<`/`@` as file input. Only its explicitly approved attachment uses `-F`. It remains a separately authorized live POST example, not an automatic helper fallback.
- Root/subskill layout and metadata shapes remain. Subskills explain that sibling helpers are optional in selective installs; standalone examples are exercised without those helpers. No generated upstream help fences exist in this repository; no upstream CLI output was rewritten. Authored helper help was updated for the actual capability changes.
- HTML file mode checks regular-file existence before plain `realpath`, which is exercised with native macOS `/bin/realpath`. Input and resolved-target suffixes must be `.html`/`.htm`; traversal rejection remains. Missing bare `.html`/`.htm` filenames in any case fail before transport; allowed file-path suffixes remain lowercase. Explicit `--file` and `--html` modes remove ambiguity without interpreting intentional markup ending in `.html` as a file. These checks do not make the filesystem a privacy sandbox or remove path races.
